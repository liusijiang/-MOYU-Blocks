## 一、当前游戏声学引擎深度审计（Current Audio Engine Audit）

### 1.1 现有架构亮点与成果
当前项目通过 `src/utils/audio.ts` 实现了基于 **Web Audio API** 的原生程序化声音合成引擎（Procedural Sound Synthesis Engine），拥有以下技术与体验优势：
1. **零外部网络资产依赖**：不加载任何 `.mp3` / `.wav` / `.ogg` 文件，首屏加载网络开销为 0，彻底免疫弱网或离线时的音频加载卡顿；
2. **零触发延迟（Zero Latency）**：直接在客户端通过振荡器（Oscillator）与瞬态包络（Gain/Envelope）即时生音，触盘、下落、锁定的响应延迟低于 $5\text{ms}$；
3. **物理参数化联动**：下落落地撞击音（`playDebrisLanding`、`playStructuralThudSound`）能根据下落物理格数动态调节基频与冲击时间；
4. **节流保护与防破音防爆音机制**：针对准星巡游（$85\text{ms}$ 节流）与双频锁定（$140\text{ms}$ 节流）实施了硬件时间门限，规避高频滑动时的音频过载。

### 1.2 现有声学系统的关键缺陷与瓶颈诊断

```
                   当前音频管线单层直连缺陷拓扑
                   
   [ 各种零散音效生成方法 ]
             │
             ├──► playPiecePlaced()  ───────┐
             ├──► playStreakSound()   ───────┤
             ├──► playSingularityBurst() ────┼──► [ AudioContext.destination ]
             ├──► playDebrisFalling() ───────┤     (无主控总线 / 无子混音 / 无侧链)
             └──► ...                        │
                                             ▼
                                  【严重缺乏环境底色与空间感】
                                  【音效并发时极易产生响度打架】
```

1. **环境底色完全缺失（Absence of BGM）**：
   - 游戏全程处于“绝对静音的环境空洞”中，只有玩家有动作时才产生瞬态点声，缺少持续的声学包围感；
   - 益智消除类游戏的心流体验（Flow State）高度依赖环境音乐（如经典《Tetris Effect》、《Blockudoku》、《Lumines》），纯离散音效无法支撑玩家长时间沉浸式“摸鱼”；
2. **缺乏主混音总线（Master Audio Routing Bus）与子分轨**：
   - 现存所有音效在生音后直接 `gain.connect(ctx.destination)`，混音拓扑完全扁平；
   - 无法独立调节“背景音乐音量”与“游戏音效音量”，UI 层仅有一个粗暴的全局静音开关；
3. **缺少空间感与环境质感（Dry Signal Only）**：
   - 当前所有合成声均为 $100\%$ 的干声（Dry Signal），缺少微混响（Reverb）与立体声空间延时（Stereo Delay），导致音效听感略显机械冰冷，与游戏设定的“宇宙引力、恒星奇点、量子共鸣”深空氛围不匹配；
4. **缺乏动态侧链避让（Sidechain Ducking）**：
   - 当奇点十字爆破（Laser Blast）或引力脉冲轰鸣时，低频与高频能量瞬间爆发，若后续引入 BGM，若无侧链压限，会导致听觉浑浊劈音或严重掩蔽效应。

## 二、背景音乐（BGM）技术选型与实现范式对比

针对单页应用（SPA）与沙箱开发环境的特性，对三种 BGM 实现方案进行横向技术评估：

| 评估维度 | 方案 A：外部静态音频文件循环（Looping MP3/OGG） | 方案 B：纯 Web Audio 程序化生成式音乐（Generative Procedural BGM） | 方案 C：混合架构（短无缝 Stem 切片 + 实时合成琶音） |
| :--- | :--- | :--- | :--- |
| **网络流量与加载** | 需下载 $3\text{MB} \sim 8\text{MB}$ 音频文件，首屏或离线存在阻塞风险 | **0 字节外部文件**，纯代码算法驱动，即刻启动 | 约 $300\text{KB} \sim 500\text{KB}$ 轻量环境底噪切片 |
| **听觉疲劳度** | 固定旋律循环，播放 5~10 分钟后易产生枯燥反感 | **无限变奏、永不重复**，算法基于马尔可夫链或五声调式随机演变 | 较低，底噪循环但旋律随机 |
| **动态游戏性响应** | 很难做到细粒度参数联动（仅能切歌或调音量） | **极高**，可根据共鸣槽百分比、连击数、狂热模式实时调制滤波与速度 | 高，可切换分轨（Stems） |
| **内存与算力消耗** | 内存占用较高（解码后 PCM 数据占数十兆） | 极低（仅使用几个低开销原生振荡器与双二阶滤波器） | 中等 |
| **综合推荐指数** | ⭐⭐⭐ (实现简单但体验平庸) | ⭐⭐⭐⭐⭐ (**强烈推荐：最具极客精神与动态可塑性**) | ⭐⭐⭐⭐ (音质最丰富但涉及素材集成) |

### 核心决议：采用【方案 B】纯 Web Audio 程序化生成式太空环境音乐引擎（Generative Cosmic Chillout Engine）
- **风格定位**：**“宇宙深空 Lo-Fi 氛围脉冲（Cosmic Ambient Chillout & Pulse）”**；
- **调性选择**：**C 大调 / A 自然小调（C Major / A Natural Minor）五声音阶体系**，与当前游戏的连击消除音效（C4~D6 五声音阶）实现 **$100\%$ 和声对齐**；
- **听觉特征**：温暖低缓的正弦长音 Pad、梦幻轻灵的五声星辰琶音（Starlight Arpeggios）、以及跟随呼吸起伏的次低频引力脉冲（Sub-bass Gravity Drone），让人心境澄明、极度解压，久听不累。

### 3.1 和声进程与旋律算法设计
- **主和弦级数（Chord Progression）**：
  $$\text{I} - \text{vi} - \text{IV} - \text{V} \implies \text{Cmaj7} \to \text{Am7} \to \text{Fmaj7} \to \text{G7sus4}$$
  - $\text{Cmaj7}$: $C3(130.81\text{Hz}), E3(164.81\text{Hz}), G3(196.00\text{Hz}), B3(246.94\text{Hz})$
  - $\text{Am7}$: $A2(110.00\text{Hz}), C3(130.81\text{Hz}), E3(164.81\text{Hz}), G3(196.00\text{Hz})$
  - $\text{Fmaj7}$: $F2(87.31\text{Hz}), A2(110.00\text{Hz}), C3(130.81\text{Hz}), E3(164.81\text{Hz})$
  - $\text{Gsus4}$: $G2(98.00\text{Hz}), C3(130.81\text{Hz}), D3(146.83\text{Hz}), F3(174.61\text{Hz})$
- **自适应调变规则**：
  - 每个和弦维持 4 个小节（约 $14.1\text{秒}$），平滑对数淡入淡出（Crossfade Duration: $2.5\text{秒}$），没有任何突兀的切和弦突变；
  - 玩家在消除方块时触发的 `playStreakSound` 产生的音阶是该和弦内音的自然延伸，玩家每一次操作都在参与即兴伴奏。

### 3.2 游戏状态与音乐反应式映射矩阵

| 游戏状态触发点 | 音乐层级调制表现（Audio Modulation） | 玩家心理声学目标 |
| :--- | :--- | :--- |
| **开局/闲置观察** | 仅 Layer 1 恒星虚空 Pad 以 $25\%$ 音量缓缓流动，低通滤波截止频率截止在 $450\text{Hz}$ | 放松、解压、进入沉浸专注态 |
| **持续平稳消除 (Streak 1~4)** | 激活 Layer 2 星辰琶音，音阶以自然五声随机点缀，BPM 维持 $68$ | 节奏愉悦，获得渐进式成就感 |

## 四、视听联觉（Synaesthesia）：音效体系深度改造与和声协同

除了引入背景音乐外，现有的点状音效需要进行**音色、空间与和声的全面升级**，使其与 BGM 融为一体而非相互割裂。

### 4.1 核心点状音效的升级改造清单

| 音效名称 | 当前实现现状 | 改造方案（次世代声学增强） |
| :--- | :--- | :--- |

| **方块下落与落地**<br>`playDebrisLanding` | 线性下扫正弦波 | **升级为“多段木质晶体撞击”**：引入谐波共振器（Bandpass Filter at $180\text{Hz}$），模拟厚重微晶方块碰撞沉降的实木/玉石质感 |

### 4.2 动态侧链闪避算法（Dynamic Sidechain Ducking Architecture）
当发生高能事件（多行消除、奇点激光爆发、全局引力坍缩）时，BGM 会瞬间造成听觉拥挤。通过程序化动态侧链系统解决：

```
   [ 高能音效触发 (Singularity Burst / 4-Line Clear) ]
                        │
                        ▼ (触发控制信号: T=0ms)
              [ Sidechain Envelope Generator ]
                        │
                        ├──────► Gain 迅速下潜至 0.35 (-9dB) [Attack: 15ms]
                        │        (给爆炸声腾出绝对纯净的动态余量)
                        │
                        └──────► Gain 随指数曲线平滑恢复至 1.0 [Release: 380ms]
                                 (音乐自然回升，绝无生硬断切感)
```

## 五、专业级分层混音拓扑结构（Master Routing Architecture）

为了实现精细化的音量管理、空间混响与侧链控制，音效引擎的内部混音路由需演进为现代 DAW（数字音频工作站）级的多总线架构：

```
                                  推荐的音频总线路由拓扑
                                  
    [ 游戏音效发生源 ] (SFX Nodes)
           │
           ├──► [ Dry SFX Bus ] ───────────┐
           │                               │
           └──► [ Reverb Send Bus ] ──┐    │
                                      │    │
    [ 生成式背景音乐 ] (BGM Generators)│    │
           │                          │    │
           └──► [ BGM Stem Gain ] ────┼────┼───► [ Sidechain Ducking Gain ]
                                      │    │               │
                                      ▼    ▼               ▼
                              [ FX Convolver / Reverb ] [ Master Submix ]
                                      │                    │
                                      └────────────┬───────┘
                                                   ▼
                                     [ Dynamics Compressor Node ]
                                     (软阈值 -4dB, 压限比 8:1 防爆)
                                                   ▼
                                         [ Master Volume Gain ]
                                                   ▼
                                     [ AudioContext.destination ]
```

### 5.1 各总线节点的职责与参数规范
1. **Master Compressor Node（硬件级总线压限器）**：
   - `threshold`: $-6.0\text{dB}$；
   - `knee`: $24\text{dB}$（超软拐点，消除一切毛刺与削波失真）；
   - `ratio`: $12:1$；
   - `attack`: $0.003\text{s}$；
   - `release`: $0.18\text{s}$；
2. **Reverb / Delay Send Bus（空间效果混响总线）**：
   - 采用纯算法合成的脉冲响应（Procedural Impulse Response）：使用指数衰减的带通滤波白噪声构建长约 $1.2\text{s}$ 的立体声微型空间混响，赋予方块消除与基石降临深邃的宇宙感；
3. **Stereo Panner Integration（全景声像调制）**：
   - 依据棋盘 $10\times 10$ 列坐标（$0 \sim 9$），将每列事件映射到声相值 $x \in [-0.75, +0.75]$，玩家在棋盘左侧放置或消除方块，声音从左耳传来，右侧操作从右耳传来，极大增强现场空间临场感。

## 七、工程实施里程碑与落地规划（Implementation Roadmap）

未来若获准进入代码实施阶段，建议将本方案划分为三个递进里程碑：

### 阶段一：总线重构与多轨音量控制（基础设施层）
- [ ] 在 `src/utils/audio.ts` 中重构混音拓扑，建立 `masterGain`、`bgmGain`、`sfxGain` 与 `DynamicsCompressor`；
- [ ] 升级 Header 音频控制，支持 BGM/SFX 的独立开关与持久化；
- [ ] 确保所有现有音效安全迁移至 `sfxGain`，零破音、零回退。

### 阶段二：生成式 BGM 引擎实现（核心音乐层）
- [ ] 编写 `GenerativeMusicEngine` 核心模块，实现 C 大调 Pad 与星辰琶音器的时钟调度；
- [ ] 接入游戏状态驱动器（State-Driven Modulator）：响应共鸣槽进度、Fever 连击数，实现音轨与滤波的动态演进；
- [ ] 验证长时间（$>30$ 分钟）挂机运行的内存稳定性与无听觉疲劳度。

### 阶段三：空间声相、微混响与侧链避让（质感提升层）
- [ ] 接入算法脉冲混响总线（Convolution/Delay Send），增强基石与奇点爆破的空间余韵；
- [ ] 接入棋盘列坐标声相映射（`StereoPannerNode`）；
- [ ] 接入高能事件动态侧链闪避（Sidechain Ducking），使 BGM 与音效呼吸交融。

## 八、总结与评审结论

本方案针对《摸鱼方块》的玩法特质，提出了**“无需外挂大体积音频文件、纯代码算法驱动、与消除音效调性天然谐调、随游戏局势呼吸演进”**的生成式宇宙氛围 BGM 体系。不仅填补了目前游戏环境底色的空白，更通过多总线架构、侧链闪避与立体声声相，使游戏的整体听觉品质提升至独立精品游戏的水准。
