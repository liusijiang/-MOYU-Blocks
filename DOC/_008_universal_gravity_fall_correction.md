## 一、需求背景与修正定位

### 1. 任务背景回顾 (004 机制的原始设定)
在 `004` 任务设计中，引入了 1x1 特殊道具——**“重力方块（Gravity Core / 1x1 重力核心）”**：
- 当玩家达成多行消除（≥2 行、≥2 列或横纵共消）时，棋盘上会生成一个带有粒子与微光的 1x1 重力方块；
- 在 `004` 的原始设定中（见 `_004_piece_debris_gravity_and_gravity_block.md` 第 22 行及第二章第 3 款）：
  > *“全场引力爆发机制：消除重力方块瞬间，全场所有静止或悬空的积木碎片共振下沉，引发震撼的全局多段大消除与极限翻盘。”*
- 即此前仅有 `isDebris === true`（曾被行/列消除切断破坏过的受损积木碎片）才会被唤醒并下沉，而玩家此前放置的、**尚未被切削过的完整积木（Intact Pieces，`isDebris === false`）依然保持静止锚定**。

### 1. “公正下坠（Fair Universal Fall）”的严谨定义
所谓“公正下坠”，包含三层递进的物理逻辑：

1. **平等性（Equality of Mass）**：
   - 无论一个积木是最初放置的完整 `3x3`、`3x1`、`L型`、`T型`，还是被消除切削后的残缺碎片，还是 `1x1` 小单格；
   - 只要引力核心被引爆，**重力对所有实体全部生效，不再区分完整或碎片**。

2. **几何刚体完整性（Rigid Body Integrity）**：
   - 每一个积木实体作为一个整体（Polyomino）向下垂直掉落，**维持自身当前的连贯外轮廓不变形**；
   - 它的最大下落距离，由该刚体**最先触碰到下方障碍物（或棋盘底边界第 9 行）的那个凸出点**决定。一旦某一点受阻，整个积木即在该高度停住；
   - 这一规则绝对防止积木散成沙子，完美传承了 `DOC 003` 的连贯积木实体质感（ConnectedPiece）。

3. **空间拓扑时序性（Topological Ordering from Bottom to Top）**：
   - 在计算下坠时，必须**严格自底向上（按实体的下边界 `bottomRow` 降序排列）**依次求解；
   - 处于下方的积木先往下落并填补最底层的空洞；
   - 处于上方的积木随后下落，刚好能够稳稳地砸在已经落稳的下方积木头顶；
   - 彻底杜绝“上层方块穿越下层方块”或“下层方块被上层方块堵在半空”的拓扑穿模 Bug。

## 三、现有代码差异与技术改造点定位

为了保证在后续真正执行代码开发时做到“最小侵入、零破坏、高内聚”，我们对现有项目代码进行了逐行审计，锁定了以下核心改造点：

### 1. 核心控制器改造：`/src/App.tsx` 中的 `handleDropPiece` 循环

#### (1) 现有逻辑现状分析 (`/src/App.tsx` 行 413 ~ 428):
```typescript
// 当前代码中：
let targetDebrisIds: Set<string>;
if (isGlobalSurge) {
  // Global surge: 仅过滤了 isDebris 或 isGravityBlock
  targetDebrisIds = new Set(
    currentEntities
      .filter((e) => e.isDebris || e.isGravityBlock)
      .map((e) => e.id)
  );
} else {
  // Local surge: 本次产生的碎片 + 漂浮的重力块
  targetDebrisIds = new Set([
    ...newlyCreatedDebrisIds,
    ...currentEntities.filter((e) => e.isGravityBlock).map((e) => e.id),
  ]);
}
```
**缺陷诊断**：
- 当 `isGlobalSurge === true` 时，它使用了 `.filter((e) => e.isDebris || e.isGravityBlock)`；
- 那些原本完好无损、未曾被消除破坏过的积木实体（`isDebris === false` 且 `!isGravityBlock`），**被完全排除在 `targetDebrisIds` 之外**；
- 导致棋盘上大片完整的积木即便脚下已经悬空成大洞，依然死死悬停在空中，无法响应引力核心的爆发。

#### (2) 008 修正后的技术实现方案：
```typescript
// 008 修正方案：
let targetDropEntityIds: Set<string>;
if (isGlobalSurge) {
  // 全局所有积木公正下坠：全场所有存活实体（无一例外）全部纳入重力作用目标！
  targetDropEntityIds = new Set(
    currentEntities.map((e) => e.id)
  );
} else {
  // 局部普通消除：维持原有的切损碎片与重力块下落
  targetDropEntityIds = new Set([
    ...newlyCreatedDebrisIds,
    ...currentEntities.filter((e) => e.isGravityBlock).map((e) => e.id),
  ]);
}
```

### 2. 算法底层验证：`/src/utils/gameLogic.ts` 中的 `computeGravityCascadeDrops`

我们需要审查 `computeGravityCascadeDrops` 是否能够无缝承受“全场积木同时下落”的算力与拓扑复杂度：

#### (1) 算法工作流程回顾：
```typescript
export function computeGravityCascadeDrops(
  board: BoardState,
  entities: PlacedPieceEntity[],
  activeDebrisIds: Set<string>
): GravityCascadeDropResult
```
1. **脱离棋盘虚拟化**：将所有在 `activeDebrisIds` 中的实体从临时棋盘 `tempBoard` 擦除，还原纯净的固定障碍物地表；
2. **自底向上排序**：
   ```typescript
   activeEntities.sort((a, b) => {
     const bottomA = a.startRow + a.shape.length - 1;
     const bottomB = b.startRow + b.shape.length - 1;
     return bottomB - bottomA;
   });
   ```
   **评估结果**：排序算法采用的是外包围盒的实际底边界 `startRow + shape.length - 1`，天然具备处理任意尺寸多联骨牌（1x1、2x2、3x3、L型、T型）的拓扑顺序！
3. **逐格射线步进探测**：
   - 对每一个实体，以当前刚体形状向下测试 `nextDrop = maxDrop + 1`；
   - 判断所有 `val === 1` 的相对点 `(targetR, targetC)` 是否触底或碰撞 `tempBoard[targetR][targetC] !== null`；
   - 若合法则递增，直到碰撞为止；
   - 碰撞定格后，立即将该实体回填并固化到 `tempBoard` 中，供位于其上方的更高实体当作坚实支点。
4. **复杂度评估**：
   - 10x10 棋盘总格数仅为 100 格，实体数量通常在 10 ~ 25 个之间；
   - 单次全量模拟耗时小于 0.2 毫秒，无任何卡顿风险，算力极为充裕。

#### (2) 边界鲁棒性保障：
- 当所有积木均纳入 `activeDebrisIds` 时，`tempBoard` 在初始阶段会完全被清空（除未激活的实体外）；
- 处于全场最低位置的积木将率先向第 9 行底边界自由落体；
- 随后较上层的积木依次紧密叠放；
- **极端测试用例**：如果全场没有任何实体碰撞障碍，所有积木将如同整体下沉到棋盘底部，形成极其工整紧凑的下层积木阵列。
