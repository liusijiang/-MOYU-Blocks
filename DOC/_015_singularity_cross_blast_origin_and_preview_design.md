## 一、议题一深度剖析：十字爆破交叉点的位置判定基准

在《摸鱼方块》引入“引力奇点十字贯穿爆破”（Singularity Cross Blast）后，该技能成为了玩家在危局时刻扭转乾坤的战略级终极武器。关于十字冲击波交点的计算原点，存在两种截然不同的设计哲学：

### 1. 方案对比与物理认知模型

#### 选项 A：以玩家鼠标/触控释放时的物理指针落点为基准（Pointer Hit-Test Anchor）
- **计算方式**:
  当玩家在棋盘上释放按键或松开手指时，捕获当前鼠标光标/触摸点 $(X, Y)$ 在棋盘网格系统中的绝对索引：
  $$\text{CrossCenter} = (\lfloor Y / \text{CellSize} \rfloor, \lfloor X / \text{CellSize} \rfloor)$$
- **表面优势**: 直觉上似乎符合“指哪打哪”的枪炮直觉。
- **致命缺陷与认知割裂**:
  1. **移动端触控偏移的灾难性破坏（Touch Offset Dilemma）**：
     在现代移动端或触屏拖拽交互中，为了防止玩家粗大的拇指遮挡积木网格，所有高质量益智积木游戏（包括本项目）均在手指触点上方增加了 $60\text{px} \sim 80\text{px}$ 的抬升投影量（Offset）。如果以手指物理释放点为爆破点，玩家松手的位置可能在棋盘外部边缘，甚至落在手牌托盘上，导致爆破中心大幅偏离玩家预期放置的方块，产生极度强烈的 Bug 挫败感。
  2. **抓取点随意性导致的“因果失真”（Grab Discrepancy）**：
     对于一个 $3 \times 3$ 的复杂积木，玩家可能捏住其左上角拖拽，也可能捏住其右下角拖拽。若以指针为准，将相同的积木放置在同一个棋盘位置，由于玩家最初抓取积木的相对触点不同，十字激光扫过的行与列居然会发生完全不可预测的漂移！
  3. **物理解释性崩溃**：
     激光能量是从积木的物质结构中爆发出的引力波，如果积木放在左边，激光交点却在玩家松手偏右的空白格子里，违背了“物体作为能量源”的物理常识。

#### 选项 B：以积木实体固化的「引力星核单元格」为基准（Fixed Core Entity Anchor）—— **终极最优解**
- **计算方式**:
  每个共鸣积木在生成时，其形态中必然蕴含一颗唯一的「高能引力星核晶元（Gravity Core Cell）」，设其在局部形状矩阵中的相对坐标为 $(r_{\text{core}}, c_{\text{core}})$。当积木放置在棋盘起始位 $(R_{\text{placement}}, C_{\text{placement}})$ 时，十字激光的交点**严格、确定、不可逆地锁定在**:
  $$\text{SingularityCenter} = (R_{\text{placement}} + r_{\text{core}}, \, C_{\text{placement}} + c_{\text{core}})$$
- **核心优势**:
  1. **100% 确定性因果律（Absolute Determinism）**：
     无论玩家是用触屏、鼠标拖拽，还是点击放置；无论拖拽抓取点在哪个像素，只要积木落在目标网格，十字爆破的位置就是绝对唯一且符合预期的。
  2. **高阶策略的运筹帷幄**：
     玩家在手牌托盘中观察积木时，就能清晰地看到那颗闪烁着金紫高能脉冲的“星核晶元”位于积木的哪个部位（例如：长条的中心点、T型的突起端、或方块的底部接触面）。玩家会像狙击手校准瞄准镜一样，精细规划将该星核送入最关键的交叉十字路口。
  3. **完美统一人机工程学**：
     指针的作用仅仅是传递“放置位置 $(R_{\text{placement}}, C_{\text{placement}})$”，而爆破原点由星核位置决定，彻底解决了触屏手指遮挡与抓取偏移的难题。

## 二、议题二深度剖析：为什么“幽灵瞄准激光预览”是该机制的灵魂？

在目前仅有普通消行预览的游戏状态下，玩家拖拽引力星块时，只能看到半透明的普通积木投影，无法直观预见十字等离子激光将射向何方。**增加实时十字瞄准预览（Ghost Blast Crosshair Reticle）不仅是必要的，而且是决定该机制能否从“能玩”跨越到“殿堂级手感”的核心质变点**。

### 1. 消除信息不对称，赋予掌控感（Agency & Mastery）
- 引力共鸣大招是玩家历经多轮消除、积攒满 100 点能量才获得的“翻盘杀手锏”。
- 如果缺乏清晰的预览，玩家在将积木移动到棋盘上方时处于“盲人开火”的焦虑状态：生怕放错了一行，导致想拆除的死局柱子没有被扫到，白白浪费整场蓄积的能量。
- **实时瞄准线赋予玩家绝对的“支配感”**：当玩家拖动积木在棋盘上巡游时，两条明亮的等离子瞄准标线随着玩家手指在整整 10 行 10 列间实时扫掠，所过之处如同高能扫描仪，玩家能清晰预知每一次微调将带来的毁灭性清场收益。

### 2. 激发“连锁推演”的深度博弈（Tactical Depth）
- 棋盘上可能散落着之前留下的 $1\times 1$ 引力方块。
- 一旦拥有了十字激光瞄准预览，玩家就会在悬停时惊喜地发现：“如果我把引力核放在第 4 行第 6 列，横向激光正好能穿透右侧的引力方块，从而在解围的同时**当场引爆 5x5 裂变震碎**并激活全局雪崩！”
- 这种在落子前就能看见“一箭双雕、连环引爆”的清晰反馈，能将玩家的多巴胺分泌提前至“悬停决策时刻”，大幅增强游戏的成瘾性与策略厚度。

## 三、引力奇点十字预览系统的完整视觉与交互架构设计

为了实现顶级益智游戏（如《Tetris Effect》、《Candy Crush》巅峰时期）的视觉张力，建议采用三层立体式瞄准预览（Crosshair HUD Hierarchy）：

```
┌─────────────────────────────────────────────────────────────┐
│ 棋盘视觉分层 (Board Z-Index Architecture)                   │
├─────────────────────────────────────────────────────────────┤
│ Layer 4: [拖拽中的高亮积木实体 + 中心星核脉冲粒子] (Z=30)     │
├─────────────────────────────────────────────────────────────┤
│ Layer 3: [等离子瞄准十字线 Plasma Laser Crosshair] (Z=25)    │
│          ├─ 横向高能瞄准光轨 (Amber/Cyan Dual-Beam Line)     │
│          ├─ 纵向高能瞄准光轨 (Amber/Cyan Dual-Beam Line)     │
│          └─ 星核对准交叉点的高频呼吸光晕 (Pulsing Reticle)  │
├─────────────────────────────────────────────────────────────┤
│ Layer 2: [被激光锁定的目标方块湮灭态预览] (Z=20)              │
│          └─ 沿十字线分布的所有既有方块泛起高频晶格微白光      │
├─────────────────────────────────────────────────────────────┤
│ Layer 1: [常规幽灵积木投影 Ghost Placement Preview] (Z=15) │
├─────────────────────────────────────────────────────────────┤
│ Layer 0: [底层棋盘网格与已放置实体] (Z=0~10)                │
└─────────────────────────────────────────────────────────────┘
```

### 1. 动态十字瞄准光轨（Plasma Crosshair Reticle）的具体参数规格
- **线宽与色调**：
  - 区别于普通消除行白色的高亮，引力星核十字预览应采用**高饱和度琥珀金渐变至高能天蓝（Amber-to-Cyan Electric Sheen）**。
  - 核心激光光束厚度为 $3\text{px}$，外围带有 $12\text{px}$ 宽度、透明度 40% 的等离子高斯模糊光晕（Neon Bloom）。
- **动态呼吸与流光（Motion Kinetics）**：
  - 瞄准线内带有向两侧高速辐射的能量粒子流（Dash-array 沿坐标轴向外平移动画），给玩家传递出“能量正在枪膛中蓄势待发”的强烈物理紧张感。
- **合法性自适应响应**：
  - 当积木处于**不可放置位置（`isValid === false`）**时：十字光线收缩为微弱的暗红暗黄色虚线，透明度降为 15%，明确告知玩家此处无法校准发射；
  - 当积木处于**有效放置位置（`isValid === true`）**时：十字激光瞬间聚拢点亮，交叉点迸发出金光十字准星，伴随微弱的触觉级电磁蜂鸣提示音。

### 2. 目标方块受击预测（Target Annihilation Hint）
- 在十字激光穿过的当前行与列中，凡是已有方块的单元格，不只是整行亮起，方块表面会呈现“即将分解”的半透明晶格化（Dissolution Glitch），透明度降低至 60%，并产生轻微的抖动，让玩家一眼看清：“松手后，这 8 个既有方块将彻底蒸发，右侧的悬空长条随后将自由滑落！”

### 3. 关联引力核心的高亮联动（Chained Core Resonator）
- 若十字预览线穿过了场上现存的某颗 $1\times 1$ 引力方块：
  - 该引力方块上方立即升起一个半透明的金色警告圆环（Range Ring），以该核心为中心的外扩 $5\times 5$ 区域被淡淡的金紫极光覆盖，直接向玩家明示：“此处即将引发超大规模区域裂变！”

## 四、技术推导与轻量级数据管线规划

在后续开发实现时，该系统完全可以在不增加任何额外渲染负担的前提下，纯靠轻量级派生计算（Zero-allocation derived state）完成：

### 1. 纯数学派生状态定义（Derived State Formula）
当且仅当玩家正在拖拽引力星块（`activeDragPiece?.isResonancePiece === true`）且棋盘产生有效悬停时：

```typescript
// 1. 获取当前积木星核相对于自身的局部偏移量 (r_core, c_core)
const coreCell = findBottomMostCellInPiece(activeDragPiece.shape);

// 2. 映射至棋盘网格绝对坐标 (Target Row & Col)
const targetCrossRow = previewPlacement.row + coreCell.r;
const targetCrossCol = previewPlacement.col + coreCell.c;

// 3. 构建瞄准预览对象
const singularityReticlePreview = {
  isValid: previewPlacement.isValid,
  centerRow: targetCrossRow,
  centerCol: targetCrossCol,
  // 十字穿透的目标整行与整列
  beamRow: targetCrossRow,
  beamCol: targetCrossCol,
  // 是否联动激活场上现有的引力方块
  chainedGravityCoreCenters: placedPieces
    .filter(p => p.isGravityBlock && (p.startRow === targetCrossRow || p.startCol === targetCrossCol))
    .map(p => ({ row: p.startRow, col: p.startCol }))
};
```

### 2. 帧率与计算开销评估
- **计算复杂度**: $O(N)$（$N$ 为场上引力核心数，通常 $\le 3$ 个），单次计算耗时 $< 0.02\text{ms}$。
- **渲染方式**: 利用纯 Tailwind CSS 绝对定位与硬件加速（`will-change: transform, opacity`），完全独立于棋盘网格的重绘周期，确保在移动端 60 FPS 极其丝滑。
