### 2. 现状与痛点剖析（“碎裂感”从何而来？）
在 `001` 任务中，我们为候选区与拖拽浮层实现了 **`ConnectedPiece` 完整实体积木组件**：
- **候选区/拖拽浮层表现**：积木各单元格之间没有缝隙（`gap: 0`），内部相交边缘消除了内边框，外部边缘具备外凸高光与阴影描边，外凸拐角自适应圆角，整体呈现为一个浑然一体、犹如实体塑料开模打造的几何积木块。
- **棋盘现有表现**：
  1. 棋盘目前由一个统一的网格 `grid grid-cols-10 grid-rows-10 gap-1 sm:gap-1.5` 构成。
  2. 当积木落子到棋盘后，其色彩信息被拆解为独立的二维数组字符串 `board[r][c] = cellColor`。
  3. 每个落入的方格在棋盘上被渲染为一个**独立的、带四周完整边框与物理缝隙的小方块**。
  4. **结果**：一个原本在候选区呈“L型”或“3×3”连贯一体的实体积木，放置到棋盘后瞬间“碎裂”为由缝隙隔开的散装小正方形，失去了实体积木的整体质感与视觉连贯性。

## 二、核心难点与矛盾冲突分析

要在棋盘上实现“保持积木和候选区样式一致，保持完整实体积木组件封装”，必须妥善解决以下三大矛盾：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   棋盘实体积木一体化面临的三大核心冲突                  │
└────────────────────────────────────────────────────────────────────────┘
                                    │
    ┌───────────────────────────────┼───────────────────────────────┐
    ▼                               ▼                               ▼
【冲突 1：网格缝隙】           【冲突 2：消除切分】           【冲突 3：多实体相邻】
棋盘网格存在 gap，导致         某一行/列被消除时，实体       不同时段放置的两个不同
天然形成离散小块；实体         积木会被截断，需要支持       积木并排贴合时，彼此应
组件要求内部必须无缝。         实体的局部形态演变。         保持独立，不可粘连融合。
```

### 1. 冲突一：底板网格槽位与实体内部无缝的几何冲突
- 棋盘必须有清晰的 10×10 槽位感，让玩家看清哪里是空格、哪里可落子；
- 但实体积木组件 `ConnectedPiece` 的核心特征是单元格间**零缝隙（`gap: 0`）**与**外轮廓统一包裹**。
- **解法推演**：棋盘的“空格底槽层”与“实体积木层”需要分层解耦，或者棋盘单元格的外边框仅针对空槽有效，已填充实体在视觉上跨越缝隙或在零缝隙网格上通过立体阴影呈现槽位。

### 2. 冲突二：整行/整列消除与实体完整性的冲突
- 经典俄罗斯方块放置玩法的规则是：凑满任一行或任一列，该行/该列清空。
- 如果放置了一个 3×3 的实体积木，当其中第 2 行被消除时，这个 3×3 实体积木会被“切”成上下两个独立的部分。
- **解法推演**：必须明确实体积木在被消除破坏后的演进状态。无论采用实体对象化管理还是网格实体元数据，必须支持形状矩阵（shape matrix）的动态镂空或基于连通域的边界重新计算。

### 3. 冲突三：不同批次放置的多个实体在棋盘上相邻时的边界隔离
- 玩家先放置了一个蓝色的 2×2 实体积木，紧接着在它旁边放置了一个绿色的 1×3 实体积木。
- **视觉要求**：
  - 蓝色积木内部 4 个小格浑然一体；
  - 绿色积木内部 3 个小格浑然一体；
  - 蓝绿交界处必须有清晰的外轮廓边框与分界，不可因相邻而误融合成一个大块。

## 三、方案对比与技术推演

针对“完整实体积木组件封装在棋盘上需要保持”的要求，我们深入设计并对比以下两种技术方案：

### 方案 A：实体对象叠加层架构（Entity Overlay Component Pattern）
- **核心思想**：
  棋盘分为两层：
  1. **底板网格层（Grid Slot Layer）**：负责渲染 10×10 个暗色空槽位与交互感知，纯静态；
  2. **已落子实体层（Placed Pieces Layer）**：棋盘上直接保留已放置实体的实例列表：
     ```typescript
     interface PlacedPieceEntity {
       id: string;               // 每次落子的唯一 ID
       color: string;            // 积木颜色
       startRow: number;         // 棋盘落点行
       startCol: number;         // 棋盘落点列
       shape: number[][];        // 当前实体剩余形态（初始等于 piece.shape）
     }
     ```
  3. **渲染实现**：每个 `PlacedPieceEntity` 直接复用 `<ConnectedPiece />` 组件！通过绝对定位摆放在棋盘对应的 `(startRow * cellSize, startCol * cellSize)` 坐标上。
  4. **消除处理**：当整行/整列消除时，找到与该行/列相交的各实体实例，将其 `shape` 对应位置置为 0。如果一个实例的所有块都被消除，则从列表中移除。
- **优势**：
  - **组件 100% 复用**：棋盘上渲染的就是 `<ConnectedPiece />` 本身，视觉风格、阴影、外边框与候选区 100% 绝对一致，完全不存在任何视觉撕裂或差异。
  - **天然边界隔离**：不同实体天然是不同的 DOM 元素，它们之间自然具备完整的外部边框与圆角，绝不发生粘连。
- **适配性**：目前的 `getPieceCellBorders` 算法已基于局部 4 邻域检测，天生支持任意多连通及被消除切断后的图形，完全平滑自适应。

### 方案 B：实体元数据网格架构（Metadata-Aware Mesh Pattern）
- **核心思想**：
  棋盘维持单一 10×10 网格，但将单元格状态从简单的颜色字符串升级为实体拓扑对象：
  `board[r][c] = { instanceId: string, color: string } | null`
- **渲染实现**：
  1. 棋盘容器移除 `gap-1`，改为 `gap-0`；空槽位通过内凹细线或暗色微边框区分；
  2. 每个格子的外边框与圆角计算根据上下左右邻格是否属于同一 `instanceId` 动态调整。
- **对比评判**：
  方案 B 是重新在 Board 内部手写一套邻域拼装逻辑，无法真正达成“完整实体积木组件封装在棋盘上保持”的目标；而方案 A 是**真正复用 `ConnectedPiece` 组件本身**，且由于独立图层，各积木之间的实体感与立体重叠感最为完美。

## 四、推荐的最佳实施方案：实体对象层与 ConnectedPiece 组件直接复用（方案 A）

结合用户的明确诉求——**“完整实体积木组件封装在棋盘上需要保持”**，推荐方案 A。

### 核心实施细则

1. **数据模型扩展 (`src/types.ts`)**：
   ```typescript
   export interface PlacedPieceEntity {
     id: string;                 // 实例唯一 ID
     color: string;              // 颜色类名
     startRow: number;           // 棋盘起始行 (0-9)
     startCol: number;           // 棋盘起始列 (0-9)
     shape: number[][];          // 实体矩阵（消除后被切除的格子标 0）
   }
   ```

2. **棋盘组件重构 (`src/components/Board.tsx`)**：
   - 维持底板 10×10 网格，负责槽位底色、点击/悬停事件分发、预消除金环高亮；
   - 在底板上方叠加实体层，直接遍历 `placedPieces: PlacedPieceEntity[]`，每一个实体直接使用 `<ConnectedPiece />` 渲染：
     ```tsx
     {placedPieces.map((entity) => (
       <div
         key={entity.id}
         className="absolute pointer-events-none"
         style={{
           top: `${padTop + entity.startRow * cellPixelSize}px`,
           left: `${padLeft + entity.startCol * cellPixelSize}px`,
         }}
       >
         <ConnectedPiece
           piece={{ id: entity.id, color: entity.color, shape: entity.shape }}
           cellSize={cellPixelSize}
         />
       </div>
     ))}
     ```

3. **落子与消除协同 (`src/App.tsx`)**：
   - **落子时**：
     构造新的 `PlacedPieceEntity` 压入 `placedPieces`，同时更新逻辑二维底板矩阵。
   - **消除时**：
     根据消除的行 `clearedRows` 与列 `clearedCols`，将对应实体局部坐标位置置零；完全清空的实体自动销毁。

4. **消除动画协同**：
   - 消除时的纯白光闪耀效果（`brightness-200`）同时作用于底板与被切除实体，棋盘物理空间零抖动。
